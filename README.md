# Job Search Assistant (Multi-Agent, Stage 2)

AI-агент, що допомагає аналізувати вакансії. Архітектура: Orchestrator (LangGraph)
координує спеціалізованих агентів.

Зараз є два агенти:

- **Researcher** — бере довільний текст вакансії та перетворює його у структуровані
  дані (назва, навички, рівень, вимоги до досвіду й англійської).
- **Analyst** — порівнює структуровану вакансію з профілем кандидата (`profile.json`)
  і дає вердикт: `apply` / `maybe` / `skip`, % збігу, що збігається, чого бракує,
  головні застереження та коротке пояснення українською.

Якщо Researcher не впорався (помилка, порожній текст) — Analyst не викликається,
граф одразу завершується.

Наступний етап додасть **Executor** (чернетка супровідного листа), без
переписування Orchestrator з нуля.

## Профіль кандидата

`profile.json` — дані про кандидата (цілі, досвід, навички, мова), які Analyst
використовує для порівняння. Відредагуй цей файл під себе: заповни навички,
роки досвіду, бажаний рівень англійської/італійської тощо.

## Запуск

```
pip install -r requirements.txt
cp .env.example .env   # встав свій GEMINI_API_KEY
python cli.py
```

Встав текст вакансії, заверши вводом Ctrl+D (Windows: Ctrl+Z, Enter).

## Тести

```
pytest -v
```

20 тестів, LLM замокано (реальних викликів Gemini при тестуванні немає).

## Структура

- `schema.py` — Pydantic-моделі `Vacancy` (Researcher) та `Analysis` (Analyst)
- `researcher.py` — агент: структурує текст через Gemini, retry + fallback-модель
- `analyst.py` — агент: порівнює вакансію з профілем, retry + fallback-модель
- `candidate_profile.py` — завантажує `profile.json`
- `profile.json` — профіль кандидата (дані для Analyst)
- `orchestrator.py` — граф LangGraph: Researcher → Analyst
- `cli.py` — запуск з командного рядка
